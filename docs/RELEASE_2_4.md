# Release 2.4.0 — motion and vertical rhythm

- No animation on/off controls or stored overrides. Full GSAP / ScrollTrigger, Motion and Lenis for normal system motion preferences; opacity-only entrance animations and inline Process illustrations for reduced-motion accessibility.
- After-hydration startup, per-engine initialization isolation, and dependency-free native animations if enhancement is delayed or fails. Timed entrance scenes complete after scrolling stops; Process and parallax remain scroll-linked. Diagnostic attributes: `motionState`, `sceneEngine`, `scrollEngine`, `interactionEngine`, `motionScenes`, `motionReveals` on `document.documentElement.dataset`.
- Theme colors crossfade for 420ms; sun/moon icons crossfade; the scroll engine and active Process stage are no longer recreated when the theme changes. Theme still defaults to light for first visits. Existing visitor theme choice is preserved.
- Section rhythm reduced from a desktop maximum 128px to 84px per major section edge, with deliberately asymmetric adjacent section edges and 60px/48px tablet/mobile spacing. Existing horizontal layout and artwork remain.
- The last Process stage reserves the illustration's height to prevent the sticky artwork disappearing too early; smaller/shorter screens and reduced motion retain all four inline examples. Final color starts earlier.
- 23 local automated tests, including 15 existing contact tests, passed. Asset references and TypeScript/JavaScript parse and CSS syntax checks passed.
- 84 Chromium layout checks (14 viewport sizes, 2 themes, home and study, full and reduced home modes) passed. Actual dependency-free fallback entrance/re-entry, forced chunk failure recovery, final Process stage/label, theme color interpolation, theme scroll retention, and narrow navigation were tested using static markup generated from the TSX. See RELEASE_2_4_BROWSER.json. This is not a full Next.js hydration/GSAP browser test. The package registry/public network is unavailable in the local tool environment; Vercel performs the production build separately.
- Existing contact API, recipient, validation and mail-intent files are unchanged. No project environment values are included or changed during deployment. SMTP delivery was not tested or triggered in this revision.
